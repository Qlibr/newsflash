Four ways to get feed data in

These hit live third-party services, so they need network access and may rate-limit. Open via npm run dev → /examples/hosted-proxies.html.

1. Same-origin XML — no proxy at all

Your own site's /feed/, or any publisher that sets Access-Control-Allow-Origin. The component parses RSS and Atom itself, so no server step is involved. (Most publishers do not send CORS headers — hnrss.org, for instance, does not.)

2. rss2json.com

Returns normalized JSON, so no parsing happens in the browser. Works without a key at a low rate limit — but count, order_by and friends are paid parameters that make the free endpoint return HTTP 422, so let the component's own limit trim the list instead. Every reader's IP and reading habits pass through a third party.

3. AllOrigins

A generic CORS passthrough — /raw returns the untouched feed body, /get wraps it in { contents: "…" }. The component handles both. No allowlist, no SLA; fine for a demo, risky as a production dependency.

4. Your own Cloudflare Worker

See examples/cloudflare-worker.js. Same shape as AllOrigins but you control the allowlist, the cache and the user agent. Swap the URL below for your deployed worker. 

<newsflash-feed
  src="https://newsflash-proxy.you.workers.dev/?url=https%3A%2F%2Fhnrss.org%2Ffrontpage"
  layout="cards"></newsflash-feed>

5. Server-rendered — no client fetch at all

What the WordPress shortcode does by default: the server embeds the items and the component reads them without a network request.
